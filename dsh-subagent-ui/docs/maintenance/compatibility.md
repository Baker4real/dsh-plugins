# 兼容性与已知边界

## Read-only projections and prompt preview

- Prompt data may be displayed **only** through the subagent-session preview path added in v1.10.0: the text is read from the child session's own `user/message` events through the plugin's retained binding — **never** from `SessionSummary.prompt`, which carries no prompt — matched to a message node **by message id** (a node key's `<anchor>` is a feed counter, not `event.seq`; a node whose own record is outside the retained window reads its **own** DOM body instead of a neighbour's record), rendered with text nodes only (no third-party markdown library, no `dangerouslySetInnerHTML` / `innerHTML`, links limited to `http(s)` / relative targets), and never written back.

- A child's type and model may be displayed, but only from the public read-only projections, probed by key, each with an explicit fallback when the host does not publish it; never add a model-switch UI or call a model write API (`selectedModel`). The type goes through the single reader `childModeOf`, whose fallback order must stay: ① the discovered catalog entry — `subagentsByParent[parentId].entries[].mode` on hosts up to **0.1.6-alpha.2**, `byId[parentId].projectionValues.subagentCatalog[].mode` on **0.1.7-rc.1** and later, with `projectionsBySession[parentId].values.subagentCatalog` as a defensive fallback and the legacy source winning whenever a host publishes both (present only once that parent's catalog was pulled — opening the manager panel is one such pull, so it must never be the only rung; an entry whose `mode` is `'unknown'` keeps its label and yields the mode to rung ②) → ② `byId[childId].projectionValues.subagent.mode` (the child's own identity projection, pushed on the live-control stream and on every session-added summary, so a freshly loaded page already has it) → ③ the existing `typeLoading` text (zh + en).

- The model is `byId[childId].projectionValues.modelSelection` → `next ?? lastUsed`, falling back to `modelUnknown`.

- Usage figures follow the same read-only rule through the single reader `usageStats` (panel detail row and active float project the same object): the billed input is `uncachedInputTokens + cacheReadTokens + cacheWriteTokens` and that billed input alone is the cache-hit denominator — never the total, which would count output tokens in a prompt-side ratio — the share is formatted with the ported official `formatCacheHitPercent`, so a partial hit can never round up to 100, and tps is `projectionValues.sessionStats.decodeTokens / (decodeMs / 1000)`; a missing bucket, a zero denominator or a non-positive decode window omits that segment (zh + en) instead of rendering 0, `NaN` or `null`.

### Catalog scope and navigation

- The plugin manages the catalog discovered by the current browser runtime; it is not a global historical subagent index.
- Exact child navigation uses `{ parentSessionId, childSessionId, mode }` when DSH supplies that address. Otherwise the UI falls back to retained session navigation.
- Archive state is browser-local and does not delete DSH sessions.

### Header shadows and uninstall

The stock `ui-subagent` plugin is intentionally left enabled: the row/floating-panel “open in the sidebar” button reuses its `subagentchat` right-sidebar tab. What keeps the stock plugin’s **two** header entries invisible is the plugin’s own declarative low-priority shadow, one registration per slot, both funnelled through `registerShadow` (catch → warn → the official entry stays visible, so a host that ever ships its own entry at the same `(id, priority)` pair costs the shadow and not the plugin; an escaping throw would tear down that `slots.inject` effect, and a synchronous one out of `inject` would fail the whole `apply`): `conversation.session.header.lineage` is a `single` slot, so `priority: -1` beats the stock registration’s default 0 outright and the crumb title renders instead of the dropdown; `conversation.session.header.actions` is a `list` slot whose cells are keyed by `id`, so a second registration at `id: "subagent-catalog", priority: -1` wins exactly that one cell (stock registers `id: "subagent-catalog", order: -30` with no priority) and renders `null`, leaving the manager’s own `subagent-workspace-manager` cell and the stock plugin’s four other registrations — including the `subagentchat` right-sidebar tab — untouched.

Re-verified on **0.1.7-rc.2**, **0.1.7-rc.1** and **0.2.0-rc.1**: on a parent session with six catalog children the header shows the stock entry nowhere and this plugin’s `🧩 Subagents 0/6` as the only subagent entry (`stock=0`, actions-slot children `2`), the six-row panel still opens, and a row’s `◫` still opens the stock `subagentchat` right-sidebar tab. **Recorded missed detection**: the stock `subagent-catalog` header entry arrived in **0.1.7-rc.1** (0.1.5-rc.3 and 0.1.6-alpha.2 register no such cell; 0.1.7-rc.1 / rc.2 / 0.2.0-rc.1 all do) and only materializes once the current session’s `subagentCatalog` projection has loaded, so the earlier matrix that recorded the 0.1.7-rc.1 header as “normal” was looking at the `lineage` slot alone — the 0.1.7-rc.2 report was the first time both cells were examined side by side, and it was never a 0.1.7-rc.2 regression. The web graph churn in 0.2.0-rc.1 (the `ui-schedule` row dropped, shortcut/telemetry rows added) still leaves this plugin’s six injected packages untouched.

- Removing the package removes its bundle patch; the host's `ui-subagent` setting was never modified, and a manually configured user stanza in `$DSH_HOME/profiles/web/cordis.patch.yml` is intentionally preserved. Verified: the user patch file is byte-identical before and after `dsh plugin --profile web remove`. Uninstalling therefore also removes **both** header shadows (they live in this plugin's own `lib/client.js`), and the stock plugin's lineage dropdown and `subagent-catalog` count entry both come back — which is the intended “no plugin, stock UI” state.
- Keep both header shadows **capacity-and-cell shaped, never version-shaped**: the stock plugin registers its lineage entry with *no* priority and its `subagent-catalog` entry with *no* priority either, so the plugin wins by declaring a strictly lower one (`-1`) in the same cell — the slots core throws only on an identical `(cell, priority)` pair and otherwise elects the lowest-priority live entry per cell (`single` slots have one cell; `list` cells are the `id`). Never raise the shadow above the stock value or probe a host version to decide whether to register; if a future host ships its own entry at `-1`, `registerShadow`'s catch keeps the official entry visible and the rest of the plugin working.

### Sidebar navigation

- The “open in the sidebar” button must stay **capability-detected, never version-checked**: it requires `ctx.get('sidebarRight').openResource`, `ctx.get('sidebarRightTabs').candidates` and `ctx.sessions.subagentAddress`, and each row's rebuilt `dsh-resource://subagentchat/session/…` address is validated with `candidates(address)` before it is used, so a format drift disables that one row's button instead of throwing at the user. Resolve both faces **per row and per click, never once at activation**: dsh **0.1.7-rc.1** registers `sidebarRight`/`sidebarRightTabs` only *after* this plugin's `apply` has run (0.1.6-alpha.2 has them at apply time), so a one-time probe silently removed the whole `◫` column there — and **0.2.0-rc.1** makes that window later still, because its `ui-sidebar-right` added `shortcuts` to its own inject list (slots/layout/locale/resources/sessions/uiSession → `+shortcuts`), so it waits for one more service before providing those faces. Verified on 0.2.0-rc.1 with a parent session carrying six catalog children: all six rows rendered an enabled `◫`, and clicking one opened that child as the stock `subagentchat` right-sidebar tab (validated by `candidates`, tab title = the child id). Those services are deliberately **not** added to the plugin's cordis `inject` list.

### Retained live output

- Live output/tool/context details come from the plugin's **own retained binding**, never from `sessions.binding(id)` alone: that call only *borrows* a binding somebody else already retained (the stock view retains just the selected session), so leaning on it made only the *selected* child stream. `sessions.retain(target, { source: 'subagentWorkspaceUi' })` returns a `SessionReference` whose `binding` stays valid until `release()`; retention is bounded and paired — the float keeps every running child it shows, the panel keeps the running rows it renders, both share `RETAIN_LIMIT` (8) with the float served first and the most recently active child first, and every row that stops rendering or stops running, every closed surface and plugin disposal releases. A host without `retain` falls back to the borrowed `binding` (capability probe, never a version check); when neither yields a binding the UI falls back to the durable summary.

排查旧 **0.1.2-alpha.2** 的事件源 API 时，再读 [该版本实现指南](../dsh-0.1.2-alpha.2-subagent-live-output-api.md)；当前保留生命周期以本节为准。

### Deleted child rows

- A **deleted child can keep a row forever** unless the HOST is asked: the manager renders `byId` entries, the host rebuilds those from the parent session's append-only log, and deleting only removes the child's session directory. The plugin therefore serves `GET /api/dsh-subagent-workspace-ui/session-entity?id=…&id=…` (also folded into the `external-status` poll as `entity`), which answers `present` / `absent` / `unavailable` from `<DSH_HOME>/sessions/<project slug>/<encodeSegment(id)>/`. The directory name is the host's `encodeSegment` (reproduced verbatim in `lib/index.js`; NOT `encodeURIComponent`), and the host's own `findLog` is the oracle in `test/session-entity.test.mjs`. The three-way answer is the rule, not a nicety: only `absent` under `root: 'read'` may hide a row, and `root: 'partial'` (a project directory that could not be listed) downgrades the rest to `unavailable` — a probe that cannot look must never read as "deleted". `test/real-data.test.mjs` replays the operator's own `~/.dsh` (read-only copy in `tmp/`, parent `session-a0f8ca99`) and is skipped unless `DSH_REAL_HOME` is set. That probe is **keyed on `[key, phase]`**, and the second dep is not decoration: deleting a child leaves the candidate id list byte-identical (the host rebuilds `byId` and the append-only catalog from the parent's log), so a probe keyed on ids alone kept its pre-delete answer and the row only vanished once the panel was reopened — a remount. `manager.ts` bumps a `entityPhase` counter on a **host-confirmed** delete only (`if(data.ok)`, both the single and the batch path) and passes it into `useSessionEntities(ids, phase)`, which replays the SAME batched request over the SAME candidates: no extra ids, no per-row request, no new timer. Nothing is hidden optimistically — the row keeps its state until the host answers, and a failed replay hides nothing (every failure arm still folds to "show"), so a replay can only confirm what the host now says.

### Terminal status

- The ended-row terminal indicator reads one field only, and that field is **generational**: `byId[childId].projectionValues.subagentTiming.lastTurnCompleted` exists from dsh **0.1.7-alpha.1** (stateVersion 3, folded from the durable `turn/end` `reason.kind === 'completed'`), while **0.1.5-rc.3** and **0.1.6-alpha.2** publish that projection as `{ settledMs, active? }` only (stateVersion 2). Their summaries and projections are otherwise **identical** for a normally finished and for an aborted child (`activity` is live-driven, and `turnOutline[0].response` can be non-empty after an abort), so on those hosts an ended row keeps the neutral dot: that absence is real, must never be upgraded to “normal end”, and must not be replaced by an in-memory guess (only a row retained at the ending instant would have one, and it is lost on refresh — worse than a steady neutral dot). Re-verified on **0.2.0-rc.1**: `dsh-subagent`'s `projection-types.d.ts` / `catalog.d.ts` / `projection.d.ts` are byte-identical to 0.1.7-rc.1 and `dsh-session-stats` / `dsh-session-projection` are unchanged, so `subagentCatalog` / `subagent` / `subagentTiming` (and therefore this generation boundary) still read the same — a child session mounted in that build showed `Ended normally` / the green ring from `lastTurnCompleted`. The sessions contract gained only an optional `fork(onCreated)` (never called here); note that these projections are pushed **per touched session**, so copying an old session's log into an otherwise idle runtime yields rows whose type/model/usage/timing stay at their fallbacks until that child session is opened.

### Mobile top layer and summary statistics

- dsh **0.2.2-rc.1** gives the conversation column a **static `transform`** in drawer mode (`drawer = viewport < 768 && !windowsTitlebar`; `.pI_x6G_frame[data-sidebar-drawer] .pI_x6G_sidebarCol{transform:translate(0)}`), and any non-`none` transform — even `translate(0)` — makes that column the **containing block for `position:fixed` descendants**. Both `position:fixed` surfaces here (`.dsh-sam-backdrop`, `.dsh-sam-active-float`) therefore resolved against the header strip and were clipped or pushed out of view; `createPortal` is not available because the DSH module loader returns `null` for `require('react-dom')`. Both now enter the **top layer** as `popover="manual"` elements (`showPopover()` on mount, `hidePopover()` in cleanup, capability-probed), with a `:popover-open` rule restating their geometry because the UA gives a popover its own `margin`/`border` (the values vary with viewport and content — clear them, never hard-code them). **Never register a `toggle` listener that closes the element**: `toggle` fires on **show** as well as on hide, so a handler that checks `matches(':popover-open')` shuts the popover the instant it opens — that shipped as a bug in v1.12.0's first attempt and is now covered by a `staysOpen` assertion plus a control reproducing `['show','hide']`. Verify visibility, not just positioning: a `display:none` element can still report `offsetParent === null`, so `offsetParent` alone never proves the surface is on screen. When measuring in an automated browser, set the viewport first (`Emulation.setDeviceMetricsOverride`) — WebBridge windows otherwise report `innerWidth/innerHeight = 0` — and shrink it below **768px**, or the drawer transform never exists and the bug cannot reproduce at 1280px+.

Also relevant to 0.2.2: `sessionStats` is registered with `summary: false`, so an unopened child's summary omits tps/turns/steps (they are omitted, never rendered as 0); this cannot be toggled from a plugin because the flag is baked into `dsh-session-stats` and the projection registry throws on a second registration of the same key with a different `summary` value.
